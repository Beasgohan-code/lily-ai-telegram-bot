# Deployment and Operations Skill

Lily is operator-hosted. A production installation requires an always-on Ubuntu host for the Telegram bot, FastAPI service, FFmpeg work, Bot API integration, managed project roots, private data, and service supervision. Development may run in the foreground; production should use systemd or an equivalent supervisor, durable volumes, least-privilege service accounts, restricted ports, and log rotation.

The bot and FastAPI service may run separately. Signed stream tokens are durable in SQLite, allowing the API service to resolve links generated by the bot process. Health checks, configuration checks, startup order, recovery steps, and deployment logs belong to the operator’s private deployment knowledge. No token, recipient ID, or `.env` value may be committed.

Repeatable updates should be pinned, staged, tested, confirmed, and auditable. A rollback must use a known approved revision and must not overwrite the persistent data store without an explicit backup and operator confirmation.
